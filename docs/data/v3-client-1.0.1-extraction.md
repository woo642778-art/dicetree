# Random Dice 2 V3 Client 1.0.1 Extraction Provenance

Date: 2026-08-16

## Source identity

V3 canonical game data was generated by read-only static inspection of the user-provided Random Dice 2 iOS IPA. The package is labelled as a modified 1.0.1 client, so it is treated as untrusted input and is never executed.

- Client version label: `1.0.1`
- SHA-256: `0341bef051315f7827466d23f3e41900d06dfa3d4994c7ecc84a89f4d1e21dd8`
- Canonical schema version: `3`
- Extractor version: `0.1.0`
- Static Unity/IL2CPP evidence: `resources.assets`, `global-metadata.dat`, `UnityFramework`

The extractor reads ZIP members and serialized text/static metadata only. It does not launch the app, invoke the executable, load dylibs, execute bundled scripts, or reproduce third-party cheat behavior.

## Canonical table coverage

The 1.0.1 extraction currently normalizes:

- `DefenderTable`: 55 dice definitions
- `DiceTreeNodeTable`: 239 Dice Tree nodes
- `PlayerPassiveTable`: 111 passive rows
- `RuneTable`: 153 rune rows
- `MinionTable`: 17 minion/boss rows
- `VersusWaveTable`: 11 wave-scaling rows
- `ProjectileAbilityTable`: 20 projectile/mechanic parameter rows retained as partial mechanic evidence
- `PerkActionTable`: supporter/perk links used by Dice Tree nodes
- localization TextAsset: Korean and English strings required by the canonical dice/tree/passive/rune/enemy data

The Dice Tree has approximately 3,705 explicit rank-cost entries after expanding the client arrays. Rank costs come directly from `RankUpGoldArr` and `RankUpStoneArr`; missing levels are not interpolated.

## Dice Tree currencies

The prior V2 screenshot interpretation of blue/red/prism-like header resources as Dice Tree rank-up currencies was incorrect and is not part of V3 canonical data.

The client table uses:

- `RankUpGoldArr` -> in-game `골드` / `Gold`
- `RankUpStoneArr` -> in-game `다이스 코어` / `Dice Core`

V3 stores the second value internally as `stone` to preserve the client field lineage, while the UI must display the localized in-game name `다이스 코어` / `Dice Core`. No `blueCard`, `redCard`, or `prismCube` value is accepted by the V3 tree-cost validator.

## Formula-confidence boundary

Static IL2CPP metadata confirms identifiers including:

- `GetAttackIntervalByRatio`
- `GetFinalAttackIntervalWithRuneEffect`
- `RT_AttackInterval`
- `PredatorDmgPerStack`
- `BonusPredatorChance`
- `InstaPredatorHpThreshold`

Their presence is recorded in `mechanic-evidence.json` with `formula: null` and partial confidence. V3 must not convert a symbol name into exact arithmetic. Exact DPS is enabled only after operation order, additive/multiplicative behavior, clamping, and dice-specific interactions are recovered sufficiently to support golden tests.

Likewise, raw values in `ProjectileAbilityTable` and `RuneTable` are verified as extracted table values, but a value is not treated as an exact combat contribution until its runtime semantic path is proven.

## Reproducibility

`tools/rd2-extract/extract.py` fingerprints the source, statically reads the required archive members, normalizes the client tables, and emits the same compact chunk layout checked into `src/game-data/`.

The committed transport is split deterministically only to keep individual repository files manageable. `src/game-data/load.ts` expands those chunks into the validated V3 canonical object consumed by the application.

For future clients, `tools/rd2-extract/diff_clients.py` compares semantic records rather than JSON text ordering and reports changes separately for dice stats, tree costs, tree topology, passives, runes, enemies, localization, and mechanic evidence. A future client must be reviewed through this diff before replacing the canonical manifest/data.

## Modified-client exclusion rule

The uploaded package contains third-party modification/injection material. None of that runtime behavior is considered authoritative Random Dice 2 game logic. Canonical values are restricted to game tables, localization, assets, and static code-path evidence attributable to the game client. Any suspicious value should be cross-checked against a future clean client before changing an already verified formula or mechanic.
